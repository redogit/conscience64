Technical reference (English)


Six UTF-8 bytes per exact 48-bit integer, represented as Float64. Length, canonical padding and SHA-256 accompany the ordered coordinates. The exact-utf8-f64/v1 format is unchanged: old envelopes still decode. Machine numbers remain JSON numbers; localized digits are presentation only.


Locale switches never translate, normalize, transliterate, reorder or trim the source. Canonically equivalent Unicode spellings remain distinct byte sequences. Source language and direction are optional presentation hints, not inferred identity or archive metadata. They are not exported in the v1 envelope. Imported source language is unknown unless you supply it. Your device needs suitable fonts; Unicode transport alone is not support for every cultural practice or sign language.


Wall-clock date, timezone and calendar are not consulted by the codec. There is no timed session expiry or recency ranking. Sequence and historical dates inside your source remain exact; release chronology stays in manifests and Git history. This is clock-independent transport, not a claim to abolish physical time or guarantee indefinite software compatibility. A byte hash is not a signature, proof of truth, encryption or compression.


No private corpus, archived source payloads or historical ZIP capsules are included. Textareas normalize editor line endings. Original file and envelope imports retain authoritative bytes separately from their preview; recovered binary downloads preserve BOM, NUL, CR and CRLF. Editing the preview explicitly starts a new text source. A browser page is not protection against local extensions or other people using the device. Functional accessibility checks are not JAWS, NVDA or conformance certification.
