# Project — Historical Recovery

Status: `ACTIVE_SOURCE_NATIVE_ARCHAEOLOGY`

## I — What do we have?

A large Library containing old code, archives, generic pasted sources, later recovery summaries, project folders, experiment ledgers, and incomplete historical indexes.

A key discovery is that later project taxonomies are useful but not exhaustive. Some older project identities survive only inside generic files, migration notes, `legacy/` archive paths, or loose-root carriers.

## R — What difference matters?

The governing distinction is:

```text
not found by current index
!=
absent from Library
```

and:

```text
semantic resemblance
!=
project identity
```

Recovery must prefer exact historical source and explicit provenance over a plausible narrative.

## P — What should we do next?

1. Follow exact file IDs, creation chronology, archive membership, migration notes, and original namespaces.
2. Preserve `UNASSIGNED`, `UNKNOWN`, and `ABSENT` as different states.
3. Record neighboring projects without substituting them for a missing carrier.
4. Promote a recovered identity only when exact source or independently supported provenance earns it.
5. Append corrections forward instead of erasing prior recovery mistakes.
