# MMO World Beta — software boundary record

## Status

`ACTIVE_PLAYABLE_BETA / NETWORKED_MMO_NOT_YET_ESTABLISHED`

This is a software/product record, not a new scientific-result record and not an admission into the historical research graph.

## Canonical surface

`play/mmo-world/` is the canonical public MMO beta root. `play/explorer-world/` remains the underlying verified single-player shard. Older or parallel MMO prototypes are integration sources, not competing canonical roots unless a later reviewed successor explicitly changes that decision.

## I — Input

A directly playable game world, deliberately slow public growth, advertising as an intake mechanism, optional Bluetooth companions, internal service discovery/monitoring, deterministic descriptive world varieties, explicit browser-local progress, strong recovery boundaries, a future networked MMO layer, and a research analytics surface capable of recording bounded software/experiment events without converting game narrative into evidence.

## R — Difference that matters

A playable single-player shard, an advertised beta, and a server-authoritative MMORPG are different deployment states. A browser-local checkpoint is not server-authoritative multiplayer state. Discovery metadata is not authorization; DNS health is not application health; a selected Bluetooth device is not a trusted companion; deterministic flavor mutation is not gameplay-state mutation; simulation or game narrative is not scientific evidence; analytics transport validity is not evidence validity.

## P — Plan

Keep the verified Explorer World as the current playable shard. Surface it at `play/mmo-world/`; keep World Variety Lab mutations deterministic, replayable, local and descriptive; retain DU-SD/1, DU-CAP/1, DU-WATCH/1 and DU-BT/1 contracts; keep DNS authoritative/internal only; require user gesture for Bluetooth; preserve explicit user-driven local save/load while server authority remains absent; grow cohorts only after safety/stability/recovery/support/cost gates remain satisfied; and route future measurable experiments through Research Analytics only when their provenance and authority boundaries are explicit.

## O — Current output

Conscience64 has a canonical MMO beta launch page that directly runs the Explorer shard and exposes companion/protocol status. Explorer World and the canonical MMO page share one versioned browser-local checkpoint on the same origin. Loading is explicit rather than automatic; deterministic world seed reconstruction occurs before bounded mutable gameplay state is reapplied. Chapter One completion can be resumed for free exploration rather than forcing a new run.

The World Variety Lab supplies curated deterministic adjective sets across light, sound, flora, fauna, motion, mood, mystery and danger without changing map, combat, progression, rewards or scientific claims. A loopback-only CoreDNS profile and deterministic DNS probe are supplied as deployment configuration. The browser can request a BLE/GATT companion explicitly and maps OS-paired gamepads into the existing game controls.

Research Analytics is deployed separately at `/analytics/`; it may carry future instrumented MMO observations, but demo/game events are not scientific evidence and the static site is not an authoritative backend.

## Local progress boundary

The versioned founding-shard checkpoint may preserve player position/health/energy, Echo Shards, bounded monster state, region visitation, Fuzzball encounter state, defeated count, current story signal, and Chapter One completion.

`LOCAL_BROWSER_CHECKPOINT != SERVER_AUTHORITATIVE_MMO_STATE`.

It does **not** establish account identity, cloud backup, cross-device persistence, anti-cheat authority, multiplayer synchronization, entitlement, moderation authority, or durable server storage. Browser storage can be cleared by the user or browser.

## Red Wilds / Arcade Forge lineage

The older `play/mmo/` Red Wilds + Arcade Forge pull request contains useful expansion ideas—data-only mini-game plugins, local-first role/activity systems, release gates and bounded Conscience64 cooperation. It predates the canonical `play/mmo-world/` launch surface and must be reconciled into that root rather than merged as a second main MMO architecture. Prize redemption remains disabled and requires separate legal, server-attestation, fraud, privacy, funding and dispute-handling gates before any activation.

## Claim ceiling

This does **not** establish live MMO networking, account/authentication security, moderation operations, payment/entitlement processing, production DNS deployment, production Bluetooth-device compatibility, age assurance, real-world prize eligibility, advertising-campaign performance, or server-authoritative persistence. Those require separate evidence.

The Explorer/ MMO Fuzzball encounter and the separately released hidden Fuzzball Alpha remain distinct from the unresolved historical Fuzzball project identity. The local checkpoint format does not change that provenance boundary.
