# MMO World Beta — software boundary record

## Status

`ACTIVE_PLAYABLE_BETA / LOCAL_DATA_ONLY_FORGE_WITH_BOUNDED_TIMING / NETWORKED_MMO_NOT_YET_ESTABLISHED`

This is a software/product record, not a new scientific-result record and not an admission into the historical research graph.

## Canonical surface

`play/mmo-world/` is the canonical public MMO beta root. `play/explorer-world/` remains the underlying verified single-player shard. Older or parallel MMO prototypes are integration sources, not competing canonical roots unless a later reviewed successor explicitly changes that decision.

## I — Input

A directly playable game world, deliberately slow public growth, advertising as an intake mechanism, optional Bluetooth companions, internal service discovery/monitoring, deterministic descriptive world varieties, a local data-only Arcade Forge, recovered mini-game ideas from the retired branch, strong recovery boundaries, a future networked MMO layer, and a research analytics surface capable of recording bounded software/experiment events without converting game narrative into evidence.

## R — Difference that matters

A playable single-player shard, an advertised beta, and a server-authoritative MMORPG are different deployment states. Discovery metadata is not authorization; DNS health is not application health; a selected Bluetooth device is not a trusted companion; deterministic flavor mutation is not gameplay-state mutation; a locally validated plug-in recipe is not authoritative game state; imported timing metadata is not trusted executable timing code; preserving core source interaction semantics is not the same as restoring the old runtime's state/reward authority; reaction time is not player worth or an accessibility gate; simulation or game narrative is not scientific evidence; analytics transport validity is not evidence validity.

## P — Plan

Keep the verified Explorer World as the current playable shard. Surface it at `play/mmo-world/`; keep World Variety Lab mutations deterministic, replayable, local and descriptive; admit useful older MMO features one bounded successor at a time; keep Arcade Forge plug-ins data-only and local; place timing behavior in trusted canonical runtime code rather than imported JSON; preserve unrepresentable old behavior as explicit remainder rather than approximating it silently; retain DU-SD/1, DU-CAP/1, DU-WATCH/1 and DU-BT/1 contracts; keep DNS authoritative/internal only; require user gesture for Bluetooth; grow cohorts only after safety/stability/recovery/support/cost gates remain satisfied; and route measurable experiments through Research Analytics only when their provenance and authority boundaries are explicit.

## O — Current output

Conscience64 has a canonical MMO beta launch page that directly runs the Explorer shard and exposes companion/protocol status. The World Variety Lab supplies curated deterministic adjective sets across light, sound, flora, fauna, motion, mood, mystery and danger without changing map, combat, progression, rewards or scientific claims. A loopback-only CoreDNS profile and deterministic DNS probe are supplied as deployment configuration. The browser can request a BLE/GATT companion explicitly and maps OS-paired gamepads into the existing game controls.

### Arcade Forge admitted successor

The useful data-only plug-in idea from the retired `play/mmo/` branch has been reconstructed inside canonical `play/mmo-world/` rather than reviving a second MMO root.

`play/mmo-world/plugin-contract.json` and `plugin-runtime.mjs` define a bounded local recipe format with `choice`, `input`, `creative`, and now `timing` mechanics. Imported data still cannot provide executable JavaScript, HTML interpretation, URLs, clocks, timer callbacks, network/server/account/multiplayer/commerce/prize authority, or reaction-time thresholds. Trusted `timing-runtime.mjs` owns timing behavior.

Forge rewards are preview metadata only. Plug-ins cannot modify canonical Explorer progression or become authoritative achievements.

### Starter Arcade content successor

The retired mini-game runtime was inspected against the admitted data contract rather than copied wholesale.

- **Monster Mood:** the four original possible displayed moods are preserved as four fixed choice recipes. The old random selection mechanism is **not** claimed preserved.
- **Cipher Snap:** all three exact retired puzzles are represented directly as input recipes.
- **Make Something:** one explicit material/purpose combination is represented as a bounded creative seed. The old random combination generator is **not** claimed preserved.
- **Redline:** now admitted through the single new `timing` mechanic. The source interaction is preserved as a random wait in `[900, 2700)` ms, a false-start path before `GO`, and monotonic reaction-time measurement after `GO`. The source success and false-start reward values are preserved as preview metadata only. The old runtime's state-changing reward authority is not preserved.

Redline status:

`CORE_INTERACTION_SEMANTICS_ADAPTED / OLD_STATE_AUTHORITY_NOT_PRESERVED`

There is no reaction-time pass/fail threshold. Reaction measurements are local practice data and are not an accessibility gate, progression requirement, player-worth metric, or prize score. Forge also exposes an immediate practice signal so a random wait is optional during preview.

Together with the duck-rescue ordinary-life example, the starter directory contains ten validated data-only recipes. `timing-runtime.test.mjs` verifies the source wait range, false start, monotonic measurement, practice signal, and cancellation with injected clocks/timers. `forge/test.mjs` validates every recipe and the timing contract; the Chrome smoke exercises false-start and practice-reaction paths.

Research Analytics is deployed separately at `/analytics/`; it may carry instrumented MMO observations, but demo/game events are not scientific evidence and the static site is not an authoritative backend.

## Red Wilds lineage remainder

The older Red Wilds branch remains preserved as a feature source. Arcade Forge, representable starter content, and the bounded Redline timing interaction are intentionally extracted successors. Other ideas from that branch—broader role/activity systems, release gates, world content, and bounded Conscience64 cooperation—remain separate candidates and are not implied implemented by these admissions.

Prize redemption remains disabled and requires separate legal, server-attestation, fraud, privacy, funding and dispute-handling gates before any activation.

## Claim ceiling

This does **not** establish live MMO networking, account/authentication security, moderation operations, payment/entitlement processing, production DNS deployment, production Bluetooth-device compatibility, age assurance, real-world prize eligibility, authoritative plug-in achievements, full behavioral identity with the retired mini-game runtime, accessibility fitness of reaction-time play, or advertising-campaign performance. Those require separate evidence.

The hidden Fuzzball game remains newly introduced and is not identified with the unresolved historical Fuzzball project. Unlisted/noindex distribution is not a security boundary.
