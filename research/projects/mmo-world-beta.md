# MMO World Beta — software boundary record

## Status

`ACTIVE_PLAYABLE_BETA / NETWORKED_MMO_NOT_YET_ESTABLISHED`

This is a software/product record, not a new scientific-result record and not an admission into the historical research graph.

## I — Input

A directly playable game world, deliberately slow public growth, advertising as an intake mechanism, optional Bluetooth companions, internal service discovery/monitoring, strong recovery boundaries, and a future networked MMO layer.

## R — Difference that matters

A playable single-player shard, an advertised beta, and a server-authoritative MMORPG are different deployment states. Discovery metadata is not authorization; DNS health is not application health; a selected Bluetooth device is not a trusted companion; simulation or game narrative is not scientific evidence.

## P — Plan

Keep the verified Explorer World as the current playable shard. Surface it at `play/mmo-world/`; add explicit DU-SD/1, DU-CAP/1, DU-WATCH/1 and DU-BT/1 contracts; keep DNS authoritative/internal only; require user gesture for Bluetooth; grow cohorts only after safety/stability/recovery/support/cost gates remain satisfied.

## O — Current output

Conscience64 has a canonical MMO beta launch page that directly runs the Explorer shard and exposes the companion/protocol status. A loopback-only CoreDNS profile and deterministic DNS probe are supplied as deployment configuration. The browser can request a BLE/GATT companion explicitly and maps OS-paired gamepads into the existing game controls.

## Claim ceiling

This does **not** establish live MMO networking, account/authentication security, moderation operations, payment/entitlement processing, production DNS deployment, production Bluetooth-device compatibility, age assurance, or advertising-campaign performance. Those require separate evidence.

The game Fuzzball remains a newly introduced easter egg and is not identified with the unresolved historical Fuzzball project.
