# Hodge Conjecture — Whole-Research Integration Map

This map answers one question: **what can each research branch legitimately contribute to the Hodge program?**

A project can contribute method, infrastructure, calibration, generators, counterprobes, or human constraints without contributing proof evidence.

## Disposition vocabulary

```text
CORE_TARGET          directly part of the Hodge mathematical target
CALIBRATION          known/special case used to validate machinery
ACTIVE_METHOD        reusable research method
ACTIVE_TOOLING       implementation/navigation support
COUNTERPROBE         designed to falsify bad mappings or assumptions
GENERATOR_ONLY       creates candidates but cannot verify them
HUMAN_CONSTRAINT     constrains conduct/output, not theorem truth
HISTORY_ONLY         provenance/lineage context
OPEN_SEPARATE        mathematically separate open problem
DORMANT_IRRELEVANT   no current consequential Hodge role
```

## Current target frontier

The most promising integrated frontier is not a universal geometric metaphor. It is a concrete **cycle-span / representation-sector deficit search**:

```text
1. Fix a variety/family and codimension.
2. Compute or source H_Hodge exactly enough for the target.
3. Construct a declared family of algebraic cycles.
4. Compute their cycle classes and exact span.
5. If symmetry is certified, decompose both sides by irreducible sector.
6. Locate a positive verified deficit.
7. Generate algebraic constructions aimed at that sector.
8. Verify the new class independently.
9. Recompute the deficit.
10. Promote only the statement actually established.
```

## What this integration does not claim

- no proof of the Hodge conjecture;
- no reduction from P vs NP to Hodge or vice versa;
- no universal four-dimensional carrier;
- no identification of the 24-cell with K3 cohomology;
- no inference that a model-generated cycle is algebraic or independent;
- no inference that every useful research method is mathematically relevant to every Hodge family.

The purpose of this map is to make the whole research corpus **available but typed**, so that useful machinery can be reused while unsupported authority cannot leak across project boundaries.
