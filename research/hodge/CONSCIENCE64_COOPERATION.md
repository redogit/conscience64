# Conscience64 Cooperation — Hodge Research

## Purpose

Conscience64 is used here as a deterministic navigation, reflow, provenance, and recovery companion for the Hodge research program.

It does not become an independent scientific witness merely by returning a matching conclusion.

## Cooperation surface

### Input (`I`)

A Hodge task must specify, when relevant:

- variety/family;
- complex dimension;
- codimension `p`;
- coefficient domain;
- cohomology degree;
- Hodge type;
- cycle family;
- symmetry/group action;
- basis or lattice convention;
- exact source/result being used;
- computation bounds.

### Reason (`R`)

Conscience64 should identify the distinction that can change the research state, for example:

- rational Hodge class versus arbitrary `(p,p)` complex class;
- special fiber versus family-level statement;
- raw cycle count versus independent span;
- group symmetry versus valid quotient;
- known theorem versus remembered theorem;
- finite verification versus uniform theorem;
- missing source versus negative result.

### Plan (`P`)

Choose the smallest adequate action:

```text
retrieve exact source
-> recover definitions/hypotheses
-> run calibration
-> compute invariant
-> search missing sector
-> counterprobe
-> widen only if the distinction remains unresolved.
```

### Output (`O`)

Every output should expose:

```text
result
+ evidence class
+ source/provenance
+ assumptions
+ tested range
+ counterprobe status
+ claim ceiling
+ unresolved remainder
+ next bounded experiment.
```

## Project cooperation map

### Operator Moonshot

Provides experiment design, calibration discipline, ablation, replication, counterexamples, and claim ceilings.

### P-vs-NP research

Provides range-avoidance search, sharing-aware counting, symmetry-promise checks, conditioning counterprobes, exact-verifier discipline, and proof admission.

### Geometry / 4D codecs

Provides observer/projection counterexamples, rank/nullspace thinking, exact transforms, and a warning that representation correctness does not establish physical truth.

### Cross-Carrier Wave

Provides source-to-target transport contracts, explicit loss/change/remainder, and prohibition on treating shared interfaces as shared proof.

### Orbit Library / Knowledge Decay

Provides source recovery, provenance, active/cold separation, and reconstruction without erasing uncertainty.

### TBCL / CSOL

Provides task-local definitions, semantic distinction preservation, reconstruction-cost thinking, and resistance to ontology leakage.

### Historical Recovery

Provides chronology, stable identity, exact source recovery, and explicit unresolved references.

### Model experiments

May generate candidates or prioritize tests. Generated structures remain hypotheses until independently verified.

## Cooperation protocol for a proposed bridge

For any cross-project bridge record:

```text
source idea:
target Hodge object:
proposed mapping:
mathematical type of mapping:
hypotheses:
what is preserved:
what can be lost:
smallest verifier:

```

A bridge remains `BRIDGE_CANDIDATE` until the actual mathematical implication is proved or sourced.

## Example: 24-cell / E6

Allowed statement:

```text
The 24 quaternionic units / binary tetrahedral group provide a representation-theoretic E6 calibration structure, and D4 provides a root-configuration footing.
```

Not automatically allowed:

```text
The 24-cell encodes K3 cohomology.
The K3 Euler characteristic 24 is caused by the 24-cell.
E6 symmetry proves algebraicity of Hodge classes.
```

Those would require additional explicit theorems.

## Example: P-vs-NP range avoidance

Allowed transfer:

```text
Search for a rational Hodge class outside the span of currently known algebraic cycle classes, then use the missing sector to target new cycle constructions.
```

Interpretation boundary:

```text
outside known span != non-algebraic.
```

It proves only that the current generator family is insufficient unless a theorem identifies the known span with the entire algebraic-cycle image.

## Correction path

When a source, computation, or bridge is corrected:

1. keep the predecessor record;
2. record the exact failing distinction;
3. downgrade dependent claims as needed;
4. add the corrected successor;
5. rerun only the downstream checks that depended on the changed relation;
6. keep unresolved consequences explicit.

This is forward-only. History is not rewritten to make the current model look cleaner.

## Current cooperative conclusion

Conscience64 can strengthen the Hodge research process by making relations, provenance, missing sectors, claim ceilings, and correction paths easier to navigate. It supplies no independent proof weight by itself.
