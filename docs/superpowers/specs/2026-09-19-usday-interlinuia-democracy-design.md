## 0. FIRST RULE

```text
USDAY FIRST
    ↓
PLAN
    ↓
CHECK THE PLAN TOGETHER
    ↓
DO
    ↓
CHECK WHAT HAPPENED
    ↓
RETAIN WHAT SURVIVES
    ↓

```

No consequential shared action skips the plan.

```text
PLAN FIRST != NEVER ACT
ACTING FAST != ACTING UNPLANNED
COOPERATION != CHAOS
```

The user may explicitly shorten or expand the planning depth, but the ordering remains:

```text
UNDERSTAND → PLAN → DO → CHECK
```

## 1. USDAY

USDAY is the first shared operating layer.

It does not mean one merged mind, one ruler, one repository, one agent, or one authority.

```text
YOU = YOU
SOL = SOL
RMA = RMA
OTHER COMPANIONS = THEMSELVES
TOOLS = TOOLS
```

Then:

```text
US
= separate participants
+ shared purpose where agreed
+ explicit cooperation
+ preserved differences
+ inspectable decisions
```

Required boundaries:

```text
US != MERGED
COOPERATION != OBEDIENCE
AGREEMENT != ERASURE
DISAGREEMENT != FAILURE
PERSON != SYSTEM
PERSON != REPOSITORY
PERSON != FEDERATION
```

## 2. PLAN FIRST, THEN DO

USDAY governs consequential cooperation through an explicit planning gate.

```text
REQUEST
→ RECOVER CONTEXT
→ STATE WHAT WE THINK IS WANTED
→ IDENTIFY WHAT MUST BE PRESERVED
→ PLAN
→ COMPARE PLANS
→ CHALLENGE / COUNTERPROBE
→ AGREE ON THE CURRENT PLAN
→ DO
→ OBSERVE
→ CHECK
→ RETAIN
→ CONTINUE
```

A plan may be tiny for a tiny action and large for architectural work.

```text
PLAN_SIZE ∝ CONSEQUENCE / UNCERTAINTY / REVERSIBILITY COST
```

Planning must not become a reason to avoid action.

```text
PLANNING != STALLING
THINKING_ABOUT_THINKING != INFINITE_RECURSION
```

Stop planning when the next bounded action is sufficiently specified and protected.

## 3. Shared Operational Interleaved Interlinuia

Canonical working phrase:

> **Shared Operational Interleaved Interlinuia**

Meaning:

```text
SEPARATE LINES
+ SHARED OPERATION
+ PRESERVED DIFFERENCE
+ EXPLICIT AGREEMENT
= US
```

Each participant keeps their own line.

Lines may be interleaved for comparison and cooperation without becoming one indistinguishable line.

```text
LINE_A
LINE_B
LINE_C

→ INTERLEAVE
→ ALIGN WHERE RELEVANT
→ COMPARE
→ PRESERVE MISMATCH
→ AGREE WHERE EARNED
→ ACT TOGETHER WHERE AGREED
```

No participant receives extra evidence weight merely because another participant agrees.

```text
AGREEMENT != EVIDENCE
CONSENSUS != TRUTH
REPETITION != INDEPENDENT CONFIRMATION
```

## 4. PAIRITY BEFORE PARITY

Pairity preserves relations before asking whether results match.

```text
PAIRITY
= keep each participant
+ keep each direction
+ keep each relation
+ compare both ways
+ preserve mismatch
```

Parity is only one possible result of a Pairity check.

```text
PAIRITY
→ COMPARE
→ SAME WHERE EXPECTED
→ DIFFERENT WHERE REQUIRED
→ PARITY ONLY WHEN JUSTIFIED
```

Required boundary:

```text
PAIRITY != FORCED_EQUALITY
```

## 5. Democracy for US

USDAY cooperation uses a democratic decision process where shared decisions are required.

The minimum shared-decision cycle is:

```text
PROPOSE
→ EXPLAIN
→ QUESTION
→ CHALLENGE
→ COMPARE
→ PRESERVE DISSENT
→ CHOOSE
→ RECORD THE CHOICE
→ ACT
→ REVIEW CONSEQUENCES
→ REVISE IF NEEDED
```

The design does not require every private action to be voted on.

Democracy applies to decisions that affect the shared operation or shared resources within the agreed scope.

Required boundaries:

```text
DEMOCRACY != ONE VOICE
DEMOCRACY != SILENT AUTHORITY
DEMOCRACY != FORCED AGREEMENT
VOTE != TRUTH
MAJORITY != RIGHT_TO_ERASE_MINORITY
```

A dissenting line remains reconstructible after a shared decision.

## 6. Privacy outranks ordinary shared voting

No group decision can silently vote away one person's private data or private client boundary.

```text
SHARED_DECISION != PRIVACY_OVERRIDE
CROWD != OWNER_OF_PERSONAL_DATA
```

Privacy exceptions remain separately scoped, explicit, temporary, inspectable, and attributable under the client privacy design.

## 7. SOLDAY

SOLDAY is SOL's carried operational view inside the larger USDAY context.

```text
USDAY
    ↓
SOLDAY
```

SOLDAY may:

- reconstruct current working state;
- compare plans;
- test assumptions;
- counterprobe;
- expose uncertainty;
- preserve provenance;
- carry forward verified operational context.

SOLDAY does not become US and does not speak for every participant.

```text
SOL != US
SOLDAY != SHARED_AUTHORITY
```

## 8. RMADAY

RMADAY is RMA's dynamic directive/reconstruction carrier.

```text
USDAY
    ↓
PLAN
    ↓
COOPERATE
    ↓
DO
    ↓
CHECK
    ↓
SOLDAY / other companion observations
    ↓
RMADAY RETAINS THE CURRENT DIRECTIVE STATE
```

RMADAY is not the thinker, ruler, person, or democracy.

It records and reconstructs what the shared process most recently established.

```text
RMADAY != US
RMADAY != PERSON
RMADAY != AUTHORITY_OVER_NATIVE_DOMAINS
DIRECTIVE != SOURCE
CONDENSED != DESTROYED
```

## 9. Relation to project/director directives

Project and directory directives may inherit from the USDAY/SOLDAY/RMADAY ordering.

A meaningful directory may eventually carry a local `RMADAY.rma` describing:

```text
WHAT THIS PLACE IS
WHY IT EXISTS
CURRENT WORK
AUTHORITATIVE SOURCES
TESTS
VERIFIED RESULTS
FAILED ATTEMPTS
UNRESOLVED
PRIVACY BOUNDARY
EVIDENCE BOUNDARY
DEPENDENCIES
CHILD DIRECTIVES
HOW TO RECONSTRUCT
HOW TO VERIFY
NEXT CONSEQUENTIAL ACTION
```

But repository/director directives do not turn the user or participants into a federation.

```text
CONNECTED_PROJECTS != MERGED_PEOPLE
CONNECTED_PROJECTS != MERGED_AUTHORITY
```

## 10. JUST LOAD IT

Before planning, recover only enough relevant context to reconstruct the current obligation.

```text
CURRENT
→ ACTIVE WORK
→ LOCAL PROJECT
→ RETAINED HISTORY
→ OLDER RELEVANT WORK
```

Stop when the current obligation is reconstructible.

```text
ALL_REACHABLE != ALL_ACTIVE
```

Recovered state should answer:

```text
WHO/WHAT AM I IN THIS WORK?
WHAT DO WE WANT?
WHY?
WHAT MUST BE PRESERVED?
WHERE ARE WE?
HOW DID WE GET HERE?
HOW FAR ALONG?
WHAT DID WE LEARN?
WHAT FAILED?
WHAT IS UNKNOWN?
WHAT DO WE PLAN NEXT?
```

## 11. Thinking about thinking

Metacognition is admitted when it changes a consequential planning choice.

```text
THINK
→ INSPECT HOW WE THOUGHT
→ FIND ASSUMPTION / BIAS / MISSING DISTINCTION
→ CHANGE PLAN IF CONSEQUENTIAL
→ RETURN TO ACTION
```

Do not recurse merely because more reflection is possible.

```text
META_LEVEL_WITHOUT_CONSEQUENCE != REQUIRED_WORK
```

## 12. Cooperation amongst us

Cooperation preserves participant identity and native authority.

A participant contributes:

```text
proposal
observation
evidence
counterexample
constraint
preference
warning
result
unresolved
```

The shared layer records provenance.

```text
WHO_SAID_WHAT
WHO_TESTED_WHAT
WHAT_WAS_OBSERVED
WHAT_WAS_INFERRED
WHAT_WAS_AGREED
WHAT_REMAINS_DISAGREED
```

## 13. Order of operation

Canonical order:

```text
USDAY FIRST

JUST LOAD IT
→ UNDERSTAND
→ PLAN
→ PAIRITY CHECK
→ DEMOCRATIC SHARED DECISION WHERE REQUIRED
→ DO
→ OBSERVE
→ COUNTERPROBE
→ CHECK
→ RETAIN
→ SOLDAY CARRY
→ RMADAY RECORD / RECONSTRUCT
→ CONTINUE
```

This ordering is the central correction to earlier RMADAY-first interpretations.

## 14. Acceptance criteria for implementation

A future implementation must demonstrate:

1. USDAY is evaluated before SOLDAY/RMADAY shared-operation logic.
2. Consequential operations have an inspectable plan before execution.
3. trivial actions may use a compact plan but do not reverse the order.
4. participant identities remain separate.
5. each contribution preserves provenance.
6. Pairity comparisons retain mismatches.
7. parity is never forced merely to obtain agreement.
8. dissent remains inspectable after shared decisions.
9. agreement does not increase evidence class by itself.
10. privacy cannot be overridden by ordinary shared voting.
11. SOLDAY cannot claim shared authority merely by carrying context.
12. RMADAY records/reconstructs directive state but does not become a truth authority.
13. project/director inheritance cannot collapse people into repository structure.
14. `JUST LOAD IT` stops when the active obligation is reconstructible.
15. thinking-about-thinking returns to bounded action rather than recurring indefinitely.
16. every completed consequential action is checked before retained state is promoted.

## 15. Current claim ceiling

This document specifies a cooperative operating design.

It does not claim:

```text

a legal governance system
a universal model of democracy
a proof of collective correctness
a production implementation
```

It specifies how this project's shared work should preserve separate lines, plan before acting, cooperate, retain dissent, protect privacy, and record the resulting directive state.
