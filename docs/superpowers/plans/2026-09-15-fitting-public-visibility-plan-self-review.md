## 1. Deterministic public artifacts must not embed the current commit SHA

Checked-in/generated files such as `public-discovery.json`, `sitemap.xml`, feeds, entry pages and reconstruction manifests MUST depend only on admitted public content, explicit public-site allowlists, stable URLs and content/source hashes.

They MUST NOT embed `GITHUB_SHA` or any runtime `source_revision`, because committing such a value changes the commit identity and makes byte-for-byte `--check` impossible.

Therefore revise the Public Visibility plan interfaces as follows:

```text
build_discovery_model(snapshot, site_paths, *, base_url) -> dict
```

not:

```text
build_discovery_model(snapshot, site_paths, *, base_url, source_revision) -> dict
```

The deterministic discovery model contains:

```text
schema
base_url
site_surfaces
research_records
snapshot_sha256
public_site_paths_sha256
evidence_boundary
```

The exact Git revision belongs only in an operation report printed to CI/logs:

```python
def operation_report(*, outputs: dict[str, bytes], source_revision: str, generated_at: str) -> dict:
    return {
        "schema": "conscience64/public-discovery-operation/v1",
        "source_revision": source_revision,
        "generated_at": generated_at,
        "outputs": {
            path: {"sha256": hashlib.sha256(raw).hexdigest(), "bytes": len(raw)}
            for path, raw in sorted(outputs.items())
        },
    }
```

`build_public_discovery.py --check --source-revision "$GITHUB_SHA"` may accept `--source-revision`, but that argument MUST affect only the printed operation report, never generated bytes.

This mirrors the existing public-update design, where the checked-in snapshot is deterministic and the exact revision is logged separately.

## 2. Fitting `add_repair` transition must be explicit

Task 4 of the Fitting Lab plan must implement `add_repair` with this contract:

```python
def add_repair(fit: dict, *, repair_id: str, direction: str, parents: list[str],
               invariant: str, outcome: str, status: str, provenance: dict) -> dict:
    if direction not in REPAIR_DIRECTIONS:
        raise FitError("invalid repair direction")
    if status not in STATUSES:
        raise FitError("invalid repair status")
    if STATUS_STRENGTH[status] > STATUS_STRENGTH[fit["claim_ceiling"]]:
        raise FitError("repair exceeds fitting claim ceiling")
    if not repair_id or not invariant or not outcome:
        raise FitError("repair id, invariant and outcome are required")
    out = _copy_fit(fit)
    if any(item["id"] == repair_id for item in out["repairs"]):
        raise FitError("duplicate repair id")
    out["repairs"].append({
        "id": repair_id,
        "direction": direction,
        "parents": list(parents),
        "invariant": invariant,
        "outcome": outcome,
        "status": status,
        "provenance": copy.deepcopy(provenance),
    })
    validate_fit(out)
    return out
```

`validate_fit` must validate every repair direction/status and reject duplicate IDs within each typed collection.

## 3. Fitting record identity excludes no semantic research fields

`fit_uoid(fit)` hashes the full validated fitting record. There is no mutable transport-only `fit_uoid` field inside the record. If a future transport wrapper adds timestamps, ledger sequence numbers or server-generated IDs, those belong outside the fitting record and therefore outside this content UOID.

## 4. Public `correction_of` relations never invent missing targets

If an admitted public record has `correction_of`, the discovery builder checks only against the already-admitted public snapshot:

```text
present admitted target -> relation_status = resolved
absent from admitted snapshot -> relation_status = unresolved
```

The builder MUST NOT open an unadmitted/private record to try to resolve the relation.

## 5. Public record entry pages must expose status as text, never color alone

Any generated status/claim-ceiling presentation must include textual labels such as:

```text
Status: CANDIDATE
Claim ceiling: OPEN
```

Color may be additive decoration only. This is the minimum accessibility requirement for semantic status distinctions.
